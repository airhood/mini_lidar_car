# Unity에서 학습 정책 평가

`ManualDrive`는 교사 데이터 수집 씬이다. `PolicyEvaluation`은 학습 모델이 스스로 움직이는 평가 씬이다. `PolicyEvaluation`에서 Play를 누르면 기본 체크포인트인 v8을 불러와 시드 1129의 복도·홀·연결형 방을 순서대로 평가한다. 배치가 끝난 뒤에는 `P`로 다시 평가할 수 있다. 검사할 시드 수나 가중치를 바꾸려면 Play 전에 `Vehicle → Obstacle Teacher`의 `First Seed`, `Seed Count`, `Evaluation Weights`를 바꾼다. `Evaluation Weights`에는 Unity용으로 내보낸 `.bytes` 파일을 지정한다. 자동 평가 CSV는 `data/policy-evaluations/`의 실행별 폴더에 남는다.

## 평가 조건

- 새로운 LiDAR 스캔이 들어올 때만 모델을 평가한다. 모델 입력은 스캔 이력, 주행 지시, 모터 명령 이력이다. 모델이 직전에 출력한 명령이 다음 입력에 다시 들어간다. 학습용 교사 경로 및 좌표는 모델 입력으로 사용하지 않는다.
- 화면의 배치와 지시는 교사와 같은 생성기·시드에서 가져온다. 한 시드당 최대 31개 슬롯이다. 정적으로 우회가 불가능한 배치는 두 주행을 함께 건너뛴다. 정적 배치 탈락은 모델의 주행 실패 수와 분리한다.
- 이동 임무는 모델이 목표 반경 0.14 m 안에 들어오면 평가기가 모터를 끄고 도달로 처리한다. 교사 기준 반경은 0.07 m다. 완전 차단은 계획 정지점 0.30 m 안에서 선속도 0.015 m/s 이하와 각속도 0.03 rad/s 이하를 0.7초 유지하면 정지 성공이다. 이 목표점은 결과 판정에만 사용한다. 실제 목표까지 상위 경로를 생성하거나 목표 감지를 하는 능력은 이 시험에서 측정하지 않는다.
- 충돌은 첫 물리 접촉에서 기록하며, 최대 65초의 시뮬레이션 시간 내에 완료하지 않은 주행은 시간 초과다. 도달·정지·충돌·시간 초과를 임무 조건별로 각각 집계한다. 정적 교사 경로가 실제 물리 주행에서 성공하는지도 같은 시드에서 확인한다.
- 미학습 시드 1129는 v8 학습 범위 1000~1119 밖이다. v12 연결 검증 모델이 실제로 학습한 시드는 1123이고, 해당 학습의 검증 시드는 1124다. v12 모델은 파이프라인 확인용 1 epoch 체크포인트이므로 성능 비교는 학습량과 목적이 다른 두 체크포인트의 진단이다.

## 배치 명령

저장소 루트에 `UNITY_EDITOR` 실행 경로를 지정한다. Unity 에디터가 같은 프로젝트를 열고 있으면 별도 검증 복사본을 사용한다.

```bash
run="$PWD/experiments/evaluation-run"
mkdir -p "$run/recordings"
"$UNITY_EDITOR" -batchmode -nographics -disableAudio \
  -projectPath "$PWD/mini_lidar_car-sim" \
  -executeMethod TeacherBatch.RunEvaluation -teacherCollect -teacherInference \
  -teacherFirstSeed 1129 -teacherSeedCount 1 \
  -teacherOutput "$run/recordings" -logFile "$run/unity.log"
python3 tools/summarize_policy_evaluation.py "$run" --output "$run/summary.json"
```

다른 모델은 `-teacherPolicyWeights <경로>`와 `-teacherPolicyName <이름>`을 준다. TorchScript 체크포인트는 `tools/export_unity_lower_policy.py`로 변환한다. 같은 씬에서 교사를 돌리려면 `-teacherInference`와 모델 관련 인자를 빼고 새 출력 폴더를 사용한다. 비교 스크립트에 여러 실행 폴더를 전달하면 시드·임무·환경·배치·지시가 일치하는지 검사한 뒤 집계한다.

## 2026-11-20 v8 모델 입력 의존성 진단

현행 하위 모델은 52,914개 파라미터의 1D CNN과 MLP다. 최근 360빔 스캔 4개를 원형 패딩 합성곱 2층과 평균 풀링으로 인코딩한다. 이 특징에 주행 지시의 원-핫 벡터 및 직전 좌·우 모터 명령을 붙인다. 은닉 유닛 64개와 `tanh` 출력 층이 현재 좌·우 모터 명령을 예측한다. 학습은 교사 명령에 대한 Smooth L1 회귀다. 배포 시 모델의 직전 출력을 다시 입력한다.

v8 미학습 시드에서 직진·좌·우·차단 정지별 12회씩 고른 48회, 12,798개 스캔에 같은 체크포인트를 적용했다. 각 조건에서 하나의 입력만 바꿨다. 기록 재생 조건에서는 관측을 고정하고 에피소드 시작에 이전 명령을 0으로 두며 다음 시점에 모델 출력을 되먹인다. 차량과 센서 관측도 달라지는 Unity 폐루프 평가와 구분한다.

| 입력 조건 | 모터 명령 MAE |
| --- | ---: |
| 직전 교사 명령 반복 | 0.00771 |
| 정상 기록 | 0.00503 |
| 지시를 고정하고 같은 지시의 다른 LiDAR 창과 교환 | 0.01340 |
| 직전 모터 명령을 모두 0으로 교체 | 0.56180 |
| 직전 회전 명령을 +0.04만큼 변경 | 0.03767 |
| 기록된 LiDAR와 지시에 모델 직전 명령을 반복 입력 | 0.23005 |

회전 명령의 변화량이 0.04 이상인 138개 스캔에서는 정상 MAE 0.02583, LiDAR 교환 MAE 0.06626이었다. 모델의 조향에 LiDAR 영향이 있고 직전 명령을 바꾸면 출력도 크게 달라진다. 그 가운데 직전 명령을 0으로 바꾸는 것은 주행 중 분포 밖 입력이므로 국소 교란과 재귀 재생을 함께 해석한다.

v8은 학습 953회에서 20 epoch를 돌렸고 전체 검증에서 교사 명령 입력 MAE 0.0045, 직전 교사 명령 반복 0.0067이었다. 추론에서 자기 명령을 사용하는 재귀 재생의 오차 및 상자 없는 임무에서도 실패한 Unity 결과는 직전 교사 명령에 의존하는 학습과 배포 조건의 불일치가 우선 원인이라는 근거다. v12 시험 모델의 학습은 27회, 1 epoch였고 좌회전 지시가 없었다. 이 모델은 데이터량, 자료 분포, 학습 시간의 효과를 분리할 수 없다. 다음 통제 비교는 같은 데이터·분할에서 직전 명령 입력 유무만 바꾸고 같은 Unity 미학습 임무에서 평가하는 방식이다.

```bash
base=experiments/unity-v8-seeds-1000-1119
python3 -m tools.audit_policy_dependencies "$base/lower-policy.pt" data/drive-recordings \
  --manifest "$base/training-files.txt" \
  --output experiments/unity-policy-evaluation/v8-input-ablation.json
```

## 2026-11-20 2D LiDAR 선행 연구와 구현 비교

가장 직접적인 비교 대상은 Pfeiffer 등의 ICRA 2017 연구다. 두 구현은 시뮬레이션의 교사 주행을 이용해 LiDAR 기반 제어 정책을 지도학습한다. 평가에서 주어지는 정보와 교사는 아래와 같이 다르다. [Pfeiffer et al., ICRA 2017, §III–IV](https://cesarcadena.ethz.ch/files/ICRA2017_mpfeiffer.pdf)

| 항목 | Pfeiffer et al. (2017) | 우리 v8·v12 |
| --- | --- | --- |
| 정책 입력 | 현재의 2D 레이저 스캔과 로봇 기준 상대 목표 위치(극좌표) | 최근 4개 스캔, 이산 지시, 직전 좌·우 모터 명령. 홀은 `Follow` |
| 출력을 다시 입력하는지 | 이전 입력 및 출력을 사용하지 않고 매 프레임 계산 | 학습에는 교사 명령, 추론에는 직전 모델 출력을 공급 |
| 제어 출력과 교사 | 선속도·각속도. 전역 Dijkstra와 로컬 DWA를 결합한 교사 | 좌·우 모터 명령. 정적 A* 경로와 기하학적 추종 교사 |
| 학습과 평가 범위 | 시뮬레이션 비교의 학습 맵 약 6,000개 궤적. 실차용 학습에는 다른 맵 약 4,000개 추가 | v8은 학습 953개, v12 연결 검증 모델은 학습 27개. 원시 궤적 수와 도메인 범위를 함께 비교해야 함 |

ICRA 연구는 순간적으로 장애물이 나타났다 사라진 시연에서 목표 쪽으로 다시 진행하는 움직임을 보였다. 실차에서 멈춘 로봇에 조이스틱 개입이 필요했고, 오목한 막다른 곳에 진입한 경우에는 스스로 빠져나오기 어려웠다고 명시했다. 논문의 결과는 상대 목표가 주어진 조건의 증거다. 목표 입력 없이 특정 지점으로 복귀한다는 증거로 사용할 수 없다. [Pfeiffer et al., ICRA 2017, §IV-E–F, §V](https://cesarcadena.ethz.ch/files/ICRA2017_mpfeiffer.pdf)

### 복귀와 학습 분포에 대한 해석

- 현재 교사는 예정 경로에 차체 위치를 투영하고 앞쪽 점을 추종한다. 그래프 맵의 비차단 임무에서는 60% 확률로 작은 측면·회전 교란을 한 번 주므로 일부 교사 복귀가 들어간다. 홀에는 이 교란이 없고, CSV에는 교란 여부나 복귀 시작·종료 표식이 없다. 기록에서 충분한 복귀 분포가 확보됐다고 결론 내릴 수 없다.
- 의도한 진행선에 돌아가는 것과 충돌 없이 자유 공간을 확보하는 것은 평가 기준이 다르다. 복도에서는 벽의 방향이나 중심이 진행선의 단서가 된다. 홀에서는 같은 스캔과 `Follow`에서 다른 출입구로 가야 하는 임무가 성립할 수 있다. 현재 폐루프 시험은 모델에 그 상대 목표를 제공하지 않으면서 도달 여부를 판정한다. 따라서 논문의 목표 도달률과 우리 결과는 직접 수치 비교가 어렵다.
- 후속 Pfeiffer 연구는 교사 시연 밖에서 정책이 만나는 상태 분포 문제를 보고하고, 모방학습으로 초기화한 뒤 실제 정책 롤아웃에 대한 강화학습을 적용했다. 다른 방법인 DAgger는 모델이 방문한 상태에 교사 행동을 붙이는 반복 수집 방법이다. 우리 회복 데이터에 이 원리를 적용하려면 Unity에서 모델이 벗어난 위치를 기록하고, 그 위치에서 교사가 통과 가능한 경로를 다시 계획해 주는 별도 수집이 필요하다. 임펄스를 넣은 교사 주행만 사용한 현재 수집과 구분한다. [Pfeiffer et al., RA-L 2018](https://las.inf.ethz.ch/files/pfeiffer18reinforced.pdf) · [Ross et al., DAgger](https://proceedings.mlr.press/v15/ross11a.html)

### 통제 비교 순서

1. 같은 v8 학습 기록, 시드 분할과 20 epoch에서 직전 모터 명령 입력만 제거한다. 같은 시드 1129의 동일한 Unity 임무로 도달·충돌·정지를 비교한다. 이 실험에서는 목표 입력이나 복귀 수집 방식을 바꾸지 않는다.
2. 상대 목표 제공의 효과는 별도로 검증한다. Unity의 로봇 기준 목표 벡터를 사용하는 실험은 입력의 정보량을 검증하는 실험이다. 실제 장비에서 같은 목표를 공급하는 방법과 오차는 별도 검증이 필요하다.
3. 복귀 데이터의 효과는 같은 모델·학습 조건에서 비교한다. 복도와 홀 양쪽에서 출발 자세 교란, 우회 도중의 편향, 실제 정책이 잘못 진행한 위치를 구분해 기록하고, 충돌하지 않고 진행을 재개하는지 확인한다. 임무에 상대 목표가 있다면 목표 거리 감소와 도달도 별도로 집계한다.

### 직전 명령을 사용하는 선행 사례

Sergeant 등의 2015년 연구도 LiDAR 이력과 모델이 직전에 생성한 명령들을 입력에 다시 넣는 운용 모드를 비교했다. 이 연구의 멀티모달 오토인코더는 학습 중 명령 입력 전체를 가리는 경우와 개별 특징을 가리는 경우를 사용했다. 센서만 쓰는 모델도 포함했으며, 시뮬레이션과 실제 복도에서 충돌 없이 달린 시간을 주 지표로 삼았다. 따라서 직전 출력 되먹임을 사용하는 모든 모델이 실패한다는 해석은 성립하지 않는다. 우리 구현은 교사 직전 명령을 계속 제공하며 학습하기 때문에 입력이 변하거나 빠진 상황에 대한 조건이 다르다. [Sergeant et al., ACRA 2015, §4.2–4.3, §5–6](https://www.araa.asn.au/acra/acra2015/papers/pap149.pdf)

### 현재 v12의 교란 표본 수

시드 1121~1123 실제 CSV 77건을 기준으로, Unity의 `System.Random`에 수집 코드와 동일한 `seed * 397 + mission / 2`의 정수 값을 사용해 교란 시점을 재계산했다. 모든 그래프 통과 주행 38건 중 18건에서 교란이 예정됐고, 그 18건 모두 예정 시점 이후까지 기록됐다. 홀·연결형 방 36건과 완전 차단 3건은 이 교란을 사용하지 않았다. 각 기록의 첫 스캔을 시간 0으로 놓으면 예정 시점부터 2초 사이에 360개 스캔(전체 28,675개의 1.26%)이 있었다. 시간 기준에 최대 한 스캔의 차이가 있을 수 있고, 이 집계는 성공적으로 복귀한 장면 수와 구분한다. ## 좌우 장애물 대조 파일럿

직전 파일럿에서는 장애물을 반영한 다음 통과 지점만으로 주행이 가능했다. 이번에는 상위 입력을 장애물과 무관한 전진 방향으로 고정하고, 실제 회피가 LiDAR 스캔에 따라 달라지는지 검사한다.

- 시드마다 실내 폭, 시작점의 좌우 오프셋, 박스의 전후 위치와 두께, 중앙선 침범 폭, 출구까지의 거리를 뽑는다. 두 주행의 벽, 출발 자세, 출구, LiDAR 노이즈 시드는 같다. 한쪽 벽에 붙어 중앙선을 넘는 장애물을 좌우 반사시켜, 왼쪽 장애물에는 오른쪽 통과만, 오른쪽 장애물에는 왼쪽 통과만 가능하게 한다.
- 동작을 기록하는 교사는 박스가 포함된 격자에서 우회 경로를 계산한다. 하위 모델에는 그 경로를 제공하지 않는다. 대신 매 스캔에 고정된 세계 전진 방향을 로봇의 현재 방향으로 회전한 두 성분과 `Follow` 지시를 준다. 이 실험에서 방향 변환에 쓰는 자세는 Unity에서 읽는다.
- 개발용 시드 2100–2127에서 28쌍을 기록한다. 24쌍은 훈련, 시드의 7 나머지가 6인 4쌍은 검증이다. 평가용 시드 2550–2559는 별도 10쌍이다. 동일한 모터 명령, 모델 구조, 학습 데이터 및 에폭으로 훈련하되 대조 모델은 학습과 추론에서 LiDAR 값을 최대 거리 상수로 고정한다.
- 차량 중심이 박스 뒷면을 0.28m 넘었는지, 박스 중앙을 올바른 쪽으로 지나갔는지, 중앙에서 ±0.50m 이내로 출구선을 통과했는지 평가한다. 같은 출발 자세인 쌍의 첫 스캔만 교환한 추론에서 초기 조향이 바뀌는지도 측정한다.
- 초기 점검에서 다음 주행으로 LiDAR의 스캔 주기가 이어져 두 첫 스캔의 자세가 미세하게 달랐다. 다음 물리 스텝에서 새 스캔을 시작하도록 변경한 후 교사 주행을 다시 기록했다. 앞선 녹화는 학습과 집계에서 제외했다. 실험 코드는 별도 브랜치 `evaluation/relative-goal`의 `34b4176`, `54c62fa`에 있다.

동일한 1D CNN 두 개를 각각 15에폭 학습했다. 두 모델의 훈련 자료는 48개 주행과 8,106개 스캔이고, 검증 자료는 8개 주행과 1,403개 스캔이다. Unity의 교사 주행 검증에서 개발용 28쌍과 평가용 10쌍 모두 시작 자세와 진행 지시가 일치했고, 박스가 좌우 반사되었으며 교사가 양쪽 모두 올바른 방향으로 피했다.

| 정책 | 완주 / 20 | 충돌 / 20 | 박스 통과 / 20 | 좌우 모두 완주한 짝 / 10 |
| --- | ---: | ---: | ---: | ---: |
| 교사 | 20 | 0 | 20 | 10 |
| LiDAR 사용 | 20 | 0 | 20 | 10 |
| LiDAR를 상수로 고정 | 0 | 20 | 0 | 0 |

같은 시작 자세의 첫 스캔을 각각 입력하고 방향 벡터와 지시를 고정한 별도 추론에서 LiDAR 정책은 10쌍 모두 조향 부호를 올바르게 바꿨다. 대조 정책의 조향은 스캔을 바꿔도 같았다. 이 결과는 한쪽 통로만 열린 Unity 시험에서 LiDAR를 이용한 회피를 확인한다. 평가 시드는 훈련과 분리했지만 같은 형식의 맵을 사용했다. 다음 단계는 같은 방향 입력으로 독립 박스, 여러 박스, 복도와 홀의 전환을 평가하는 것이다. 방향을 제공하는 실제 센서 동작은 별도로 검증해야 한다.

## 독립 박스, 연속 박스, 복도에서 홀로 전환

좌우 대조용 맵으로 학습한 모델을 고정하고 처음 보는 맵 유형에 적용했다. 독립 박스 한 개, 진행 방향을 따라 좌우로 배치된 박스 세 개, 좁은 복도에서 홀로 나오며 박스 두 개를 만나는 유형을 추가했다. 시드별로 실내 폭, 박스 크기·위치, 복도 입구 폭·길이와 출발 위치를 표본 추출했다. 유형별 좌우 반사 맵 두 개와 장애물이 없는 대조 맵 한 개를 만들었다. 입력은 이전 실험과 같은 전진 방향과 최근 LiDAR 4프레임이다. 정책을 평가할 때는 교사 우회 경로를 계산하지 않았다. 박스를 전부 벗어난 위치에 출구선을 두어 벽과 여유가 있는 어느 쪽으로든 통과하면 완주로 집계했다.

- 평가 시드 3100–3104에서 총 35개 임무를 교사와 기존 모델에 동일하게 적용했다. 교사는 35건을 모두 완주했다.
- 기존 모델의 완주는 독립 박스 9/10, 연속 박스 0/10, 복도→홀 4/10, 빈 공간 5/5였다. 연속 박스 10건 중 7건은 첫 박스까지 통과했고, 2건은 박스 세 개를 모두 벗어났지만 출구선에 닿기 전에 시간 초과됐다.
- 연속 박스나 복도·홀 전환의 데이터 가치가 있는지 확인하기 위해 개발 시드 3200–3209에서 같은 방식으로 별도 녹화를 수집했다. 시드 3204와 3209는 검증, 나머지는 훈련으로 사용한다. 기존 좌우 대조용 녹화도 학습에 포함한다. CNN 구조와 15에폭은 유지한다. 이 비교에서는 데이터의 양도 늘어난다.
- 절차적 맵, 학습 및 분석 코드는 실험 브랜치 `evaluation/relative-goal`의 `ce973cc`에 있다.

개발용 교사 주행 70건이 모두 완료됐다. 기존 좌우 대조와 새 유형을 합친 학습 세트는 104 에피소드와 20,716 스캔, 검증 세트는 22 에피소드와 4,464 스캔이다. 새 유형에서 추가한 56개 학습 에피소드는 독립 박스·연속 박스·복도→홀 각각 16건과 빈 공간 8건이다. 같은 평가 맵의 배치 주행에서 다음 결과를 얻었다.

| 맵 유형 | 기존 모델 완주 | 혼합 학습 모델 완주 | 기존 → 혼합 충돌 |
| --- | ---: | ---: | ---: |
| 독립 박스 | 9/10 | 10/10 | 1 → 0 |
| 연속 박스 | 0/10 | 3/10 | 2 → 5 |
| 복도→홀 | 4/10 | 8/10 | 5 → 1 |
| 빈 공간 | 5/5 | 5/5 | 0 → 0 |
| 전체 | 18/35 | 26/35 | 8 → 6 |

연속 박스에서는 혼합 모델이 전 사례의 첫 박스를 통과했고, 5건에서 세 박스를 모두 지났다. 완주는 3건이었고, 충돌 5건 모두 첫 박스 이후였다. 실측 예시인 3103/2에서 혼합 모델은 마지막 박스도 벗어났으나 출구선 전에 되돌아왔다. 기존 좌우 대조 시험에서는 20건 모두 박스를 통과했고 19건이 출구선을 통과했다. 1건은 박스 통과 후 시간 초과였다.

다음 수집은 첫 박스를 지난 뒤 차량의 위치·각도를 다르게 두고 다음 박스에 접근하는 상황을 우선한다. 맵 다양성과 학습 데이터 양은 이번 비교에서 함께 바뀌었으며, 연속 회피의 충돌률이 높아 이 모형을 실차 배치 후보로 채택하기에는 이르다.

## 첫 회피 이후 실제 정책 자세에서 복귀

기존 연속 박스 평가에서는 첫 박스를 통과한 뒤 충돌이 집중됐다. Unity에서 개발용 연속 박스 시드 3200–3209의 양쪽 변형을 최신 혼합 모델로 다시 주행하고, 첫 박스 후면을 0.30m 지난 뒤 두 번째 박스 앞에 있는 자세를 모았다. 장애물·벽과 0.43m 이상 떨어져 있고, 거의 같은 전후 위치의 교사 자세와 좌우 0.12m 또는 방향 8도 이상 차이가 나는 실제 정책 자세를 선택했다. 각 자세에서 속도를 0으로 초기화해 재출발한다. Unity 교사는 초기 자세에서 남은 충돌체를 반영해 경로를 다시 계획하고, 완주까지의 LiDAR·진행 방향·모터 명령을 기록한다.

20개 임무에서 15쌍을 골랐다. 선택한 짝의 좌우 위치 차이 중앙값은 0.371m, 방향 차이 중앙값은 32.83도였다. 나머지 5건은 이 구간에서 조건을 만족하는 짝을 얻지 못했다. 두 정책은 공통 혼합 학습 자료에 정상 재출발 또는 정책 자세 재출발만 같은 에피소드 수로 더하고, 같은 구조와 15에폭으로 학습한다. 성공 주행이 두 조건에 모두 있는 훈련 시드의 짝만 더하며, 기존 검증 자료는 공통으로 유지한다. 비교는 기존 평가 시드 3100–3104와 새 시드 3400–3404의 연속 박스 각 10건을 처음부터 주행시키는 방식으로 진행한다. 구현은 실험 브랜치 `evaluation/relative-goal`의 `36e1de0`에 있다.

교사는 짝을 이룬 30개 재출발 주행을 모두 완주했다. 매 주행의 첫 스캔 자세가 요청한 좌표에서 1mm, 방향에서 0.1도 이내인지 검증했다. 두 모델은 공통 104개 에피소드에 각 조건의 짝 11개를 추가해 115개 에피소드로 학습했다. 정상 자세 조건은 22,655개, 정책 자세 조건은 22,817개 학습 스캔을 사용했다. 검증 세트 22개 에피소드와 4,464개 스캔은 공통이다.

| 학습 조건 | 기존 평가 완주 / 10 | 새 평가 완주 / 10 | 첫 박스 이후 충돌 / 20 | 시간 초과 / 20 |

두 재출발 모델은 총 충돌이 같았고, 실제 정책 자세를 사용한 모델에서 시간 초과가 줄었다. 남은 충돌은 새 평가 시드 3400의 임무 3에서 발생했다. 첫 박스를 통과한 후 두 번째 박스 앞 구간에서 방향을 잃고 출발 쪽으로 돌아온 뒤 측벽에 닿았다. 이 실험은 같은 연속 박스 생성기의 새 시드까지 검사했다. 다른 맵 유형에서의 성능 유지와 실차 동작은 별도로 평가해야 한다. 본수집에서는 기존 맵 유형을 유지하고, 연속 회피 구간에 실제 정책이 방문한 자세에서의 교사 복귀를 포함한다.

## 최신 복귀 모델의 기존 전체 코스 재평가

재출발 데이터를 추가한 최신 가중치를 이전과 동일한 시드 3100–3104의 35개 코스에 적용했다. 지형, 시작 자세, 진행 방향과 LiDAR 조건이 같은지 평가 도구로 대조했다. 이번 재평가의 연속 박스 10건은 앞 절의 기존 평가 10건과 같은 임무다.

## 짧은 장애물 간격과 비스듬한 홀 입구의 평가

최신 복귀 정책의 가중치를 고정해 시드 4200–4203의 새 코스 24건을 평가한다. 맵은 세 종류로 나누고 시드마다 좌우 반사 쌍을 만든다. 훈련 데이터에 쓰지 않은 구조와 시드다.

- 짧은 간격. 네 박스를 번갈아 배치하고 앞 박스 후면부터 다음 박스 전면까지 간격을 0.79–1.00m로 뽑는다.
- 비스듬한 입구. 2.02–2.36m 길이 복도의 중심을 0.53–0.76m 옆으로 옮긴 후 홀을 열고, 입구 뒤에 박스를 둔다. 벽은 12개의 좁은 축 정렬 구간으로 근사한다.
- 벽 가까운 연속 회피. 폭 3.04–3.48m 공간에서 폭이 넓은 박스를 양쪽에 엇갈려 배치해 옆 통로를 좁힌다.

진행 방향 입력은 이전 실험처럼 세계 좌표의 전진 방향을 현재 로봇 자세로 변환한다. 교사와 모델의 시작 자세, 벽, 상자, LiDAR 잡음 시드는 동일하다. 교사의 통과 여부와 모델 결과를 모두 기록하고, 교사가 끝까지 통과한 코스에서 완주, 충돌, 시간 초과와 첫 장애물 이후의 진행을 비교한다. 구현은 실험 브랜치 `evaluation/relative-goal`의 `feb1220`에 있다.

교사는 22건에 완주했다. 벽 가까운 유형의 시드 4203 두 건은 교사 계획기가 요구 여유를 만족하는 경로를 찾지 못해 정책 비교 분모에서 제외했다. 모델은 요청한 24건을 모두 실행했다.

모델은 비교 대상 22건 모두에서 첫 박스 후면을 0.28m 이상 넘었다. 비스듬한 입구의 시간 초과 5건 중 3건은 두 박스를 모두 지났고, 예시 4201/3은 홀 안에서 돌아 나와 출발 부근으로 돌아갔다. 벽 가까운 회피의 충돌 3건은 두 박스를 통과한 이후에 발생했다. 다음 수집에서 입구를 지난 뒤 진행 방향을 다시 잡는 구간, 두 번째 회피 이후 벽 가까이에서 다음 박스에 접근하는 구간과 같은 가중치의 정상 통과 자료를 우선한다. 이 평가의 시드는 그 수집에 사용하지 않는다. ## 난이도 높은 복귀 데이터의 학습량 통제 비교

시드 4300–4305에서 수집한 비스듬한 입구·벽 가까운 재출발 파일럿의 훈련용 15쌍을 비교한다. 두 모델은 공통 115개 에피소드의 22,817개 학습 창과 동일한 22개 에피소드 검증 세트를 사용한다. 정상 자세와 실제 정책 자세 쌍마다 짧은 에피소드와 같은 수의 창을 사용하고, 더 긴 에피소드에서는 전체 시간 구간에 고르게 분산된 지점을 뽑는다. 학습 창 하나의 최근 LiDAR 스캔 4장은 원래 연속 순서를 유지한다. 이 방법으로 두 모델 모두 새 에피소드 15개에서 1,258개 창을 추가했다. 각 모델 총량은 에피소드 130개, 학습 창 24,075개다. 두 모델은 같은 1D CNN, 초기 난수 시드, 15에폭과 검증 기준으로 학습한다.

평가는 시드 4200–4203에서 이전과 같은 초기 자세와 진행 방향으로 수행한다. 교사가 통과한 22건이 비교 대상이다. 이 평가 맵은 훈련에 쓰이지 않았지만, 평가 실패를 바탕으로 새 수집의 우선순위를 정했다. 독립 추가 평가와는 구분한다. 구현은 실험 브랜치 `evaluation/relative-goal`의 `cc6f89a`에 있다.

| 조건 | 짧은 간격 완주 | 비스듬한 입구 완주 | 벽 가까운 회피 완주 | 전체 완주 | 충돌 | 시간 초과 |

| 실제 정책 자세 재출발 추가 | 0/8 | 5/8 | 1/6 | 6/22 | 8 | 8 |

정상 재출발이 원래 실패가 많았던 두 유형에서 효과를 보였다. 짧은 간격에서는 완주가 그대로였고 충돌은 1건에서 2건으로 늘었다. 실제 정책 자세 조건은 전체에서 성능이 악화됐다. 이 조건의 학습용 시작 자세 15건 중 10건은 같은 전후 위치의 교사 자세와 방향 차이가 90도 이상이고, 방향 차이 중앙값은 121.91도였다. 이 표본 편중이 회귀의 원인인지는 별도 비교가 필요하다. 정상 통과를 기본으로 두고, 복귀 표본은 작은 편차부터 큰 편차까지 나눠 검증한다. 정상 재출발 조건의 기존 일반 코스 성능은 아직 재평가하지 않았다. 두 조건의 비교는 각각 한 번 학습한 결과다. ## 정상 재출발 모델의 기존 코스와 독립 시드 검증

어려운 코스에서 19/22를 기록한 정상 재출발 모델의 가중치를 고정한다. 시드 3100–3104의 기존 코스 35건에서 이전 복귀 모델(35/35)과 비교한다. 새로운 평가는 훈련이나 재출발 표본의 선택에 사용하지 않은 시드 4500–4503으로 고정했다. 앞서 평가한 세 가지 어려운 코스 생성 유형을 사용하되 벽, 박스와 시작 자세는 새로 뽑는다. 새 시드에서는 교사와 이전·후보 모델을 같은 조건으로 다시 달리게 한다. 교사가 완주한 코스만 모델 비교에 포함하며, 완료·충돌·시간 초과와 각 모델만 성공한 사례 수를 집계한다. 도구는 실험 브랜치 `4849eaf`에 있다.

## 큰 실내 공간과 시계열 모델 비교

17–26m 폭, 21–27m 길이의 큰 실내 평면을 만든다. 개방형 홀에 가구를 흩뿌리는 유형, 더 크고 불규칙한 장애물 섬을 배치하는 유형, 서로 어긋난 개구부를 가진 칸막이 유형을 사용한다. 장애물의 위치와 크기, 시작 위치, 통과선을 시드별로 뽑는다. 큰 맵에서 평가하는 임무는 고정 전진 지시의 장애물 회피다. 교사에게는 전체 지형을 이용해 모터 정답을 만들도록 하고, 정책에는 기존처럼 최근 LiDAR 4개와 현재 차체 기준 진행 방향만 준다. 걸리는 거리가 길어 시간 제한은 시뮬레이션 115초로 정한다.

시드 6100–6105의 교사 주행을 기존에 선택한 130 에피소드 자료에 추가한다. 새 자료의 마지막 시드는 검증에만 사용한다. 6200–6203은 모델 학습과 검증에 사용하지 않고 Unity 폐루프 평가를 위한 시드로 둔다. 이전 CNN, 큰 맵 데이터를 추가한 CNN, 같은 데이터로 학습한 CNN+GRU를 비교한다. CNN+GRU는 기존 공간 CNN 뒤의 모터 예측에 시간 분기를 추가한다. 스캔을 12개 각도 구간으로 나누고 최근 4개 시점의 최소 거리 벡터를 폭 16의 GRU로 요약한다. 입력 시간 길이는 두 모델이 같다. 매 추론에서 네 스캔을 요약하므로 GRU 상태는 에피소드 전체를 저장하지 않는다. 파라미터 수는 CNN 52,914개, CNN+GRU 55,378개다.

배포 코드의 합성 입력 30개에서 PyTorch와 동일 가중치를 실행해 좌우 모터 출력의 최대 절대 차이를 확인했다. CNN은 약 6.29e-8, CNN+GRU는 약 4.97e-8이었다. 생성·학습·Unity 실행 코드는 실험 브랜치 `f6444c2`에 있다. [출력 정합 검사](../experiments/large-arena-pilot/parity/summary.json)

| 모델 | 가구가 흩어진 홀 완주 | 큰 장애물 군집 완주 | 어긋난 칸막이 완주 | 전체 완주 | 충돌 | 시간 초과 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 이전 CNN | 2/4 | 0/4 | 0/4 | 2/12 | 3 | 7 |

개발용 교사 18건과 별도 평가용 교사 12건이 모두 완주했다. 두 새 모델 모두 기존 자료에 큰 맵 주행 15건을 더한 145 에피소드와 31,840개 학습 창을 사용했다. 검증 세트는 큰 맵 3건을 포함해 25개 에피소드였다. 큰 맵을 학습에 추가한 CNN은 이전 CNN보다 완주가 7건 늘었고, 충돌은 두 모델 모두 3건이었다. 같은 입력 길이의 GRU 분기는 이 시험에서 별도의 개선을 보이지 않았다. 칸막이와 문 통과 성능의 격차가 남는다. 이 평가는 세 생성 유형의 독립 시드 12건과 고정 전진 지시에 한정한다. 다음 모델 비교에서는 동일 데이터 위에서 관측 기간을 별도 변수로 두고, 칸막이 진입과 통과 장면을 더 다양하게 수집한다. ## 문 통과 데이터 및 LiDAR 관측 시간 비교

큰 공간에 문이 있는 칸막이 두 줄을 둔다. 문 폭을 바꾸는 유형, 두 문의 중심을 좌우로 어긋나게 두는 유형, 문 뒤에 추가 박스를 배치하는 유형을 각각 생성한다. 폭 범위는 1.6–3.3m이고, 출발 위치는 첫 문의 중심에서 1.05–2.25m 옆으로 둔다. 첫 문의 방향을 향하되 자세에 임의 편차를 더해 시작한다. 이전 큰 맵과 같은 방식으로 주행 방향은 세계 좌표의 전진 방향을 로봇 기준으로 변환하며 두 교사·정책 간 시작 자세와 지형은 같다.

개발 시드 6300–6305의 성공한 교사 주행을 기존 자료에 더한다. 6400–6403은 새 평가 시드다. 이전 큰 맵 CNN과, 동일한 교사 자료를 추가 학습한 두 CNN을 비교한다. 두 새 CNN은 입력 수와 가중치 구조가 같고 한쪽은 최근 0.0·0.1·0.2·0.3초, 다른 쪽은 0.0·0.5·1.0·1.5초 시점의 스캔을 받는다. 따라서 관측 범위와 샘플 간격의 비교다. 에피소드 시작에 충분한 기록이 없으면 첫 스캔을 사용한다. PyTorch와 Unity C#의 합성 입력 32개 최대 모터 출력 차이는 두 간격 모두 6e-8 이하였다. 구현은 실험 브랜치 `56852c9`에 있다. [입력 간격 정합 검사](../experiments/doorway-history-pilot/parity/summary.json)

문 통과 개발 코스에서는 교사가 18건 중 14건, 평가 코스에서는 12건 중 10건을 완주했다. 나머지는 요구 여유를 만족하는 경로가 없어 제외했다. 두 새 모델은 문 통과 학습 주행 12건을 더한 동일한 157 에피소드와 38,761개 학습 창을 사용했다. 검증 세트도 27 에피소드와 7,223개 학습 창으로 일치한다.

## 벽·문 기반 상위 방향 지시 비교

문 코스의 고정 전진 벡터와 다음 문을 바라보는 단위 방향 벡터를 비교한다. 첫 문을 통과하기 전에는 첫 문, 통과 후에는 두 번째 문 방향을 준다. 개구부 중심의 약간 뒤쪽을 바라보고, 차체 중심이 벽 후면을 0.28m 넘으면 다음 문을 선택한다. 두 번째 문을 지난 뒤에는 원래 전진 방향을 준다. 방향 계산은 벽의 개구부와 Unity가 제공한 현재 위치만 사용한다. 박스와 교사 우회 경로는 방향 계산에 사용하지 않는다.

고정 방향 기준은 앞 절의 0.3초 CNN이다. 비교용 CNN은 동일한 데이터, 학습 구조와 15에폭을 사용한다. 문 코스 교사 녹화 14건, 7,999개 행은 방향 벡터 열 두 개만 다시 계산했다. LiDAR, 움직임과 모터 정답 등 나머지 열이 동일함을 검증했다. 이전 문 평가 6400–6403과 독립 시드 6500–6503에서 같은 교사 검증 기준으로 첫 문, 두 번째 문, 최종 완주와 충돌을 비교한다. 구현과 감사 도구는 실험 브랜치 `905d4d9`에 있다.

문 방향을 제공하면 두 번째 문 통과는 늘었으나 그중 4건이 최종 출구까지 도달하지 못했다. 새 시드 6502/0에서 고정 방향 모델은 첫 문 뒤에서 배회했고, 문 방향 모델은 두 번째 문과 출구를 통과했다. 두 번째 문 통과 직후 지시는 고정 전진으로 돌아오므로, 후속 실험에서 출구 방향까지 벽 기반으로 연결했을 때의 효과를 별도로 확인할 수 있다. 이 결과는 정확한 Unity 위치로 계산한 상위 지시의 효과를 보여준다. ## 두 번째 문 이후 출구 방향 안내 비교

같은 157개 학습 에피소드와 동일한 CNN으로, 두 번째 문을 지난 뒤 전진 방향으로 돌아오는 정책과 계속 출구를 향하는 정책을 비교한다. 새 지시는 두 번째 문 후면을 차체 중심이 0.28m 지난 뒤 시작한다. 벽과 평가에서 정한 출구선의 중심만 사용하며, 겨냥점은 출구선 0.60m 뒤다. 환경 내 박스는 LiDAR로 관측되며 방향 벡터 계산에는 들어가지 않는다.

## 같은 두 번째 문 통과 자세에서 출구 지시 교차 비교

## 실제 정책이 두 번째 문을 빠져나온 자세에서 재출발

앞의 21개 코스에 대해 문 안내 모델과 출구 안내 모델의 전체 주행 CSV를 사용했다. 두 모델별로 두 번째 문 뒤 0.42–1.10m 구간에서 충돌 전 첫 안전 스캔을 찾았다. 교사 자세와 좌우 편차 및 방향 차이가 더 큰 쪽을 코스마다 한 건 선택했다. 해당 전체 주행의 완주 여부는 선택 점수에 사용하지 않았다. 선택된 18개 자세는 전체 주행이 완주한 13건, 시간 초과 3건, 충돌 2건에서 나왔다. 3개 코스는 두 모델 모두 조건에 맞는 스캔이 없었다.

교사는 실제 정책 자세에서 시작한 18건을 모두 완주했고, 두 모델의 네 조건에서 시작 좌표와 각도가 동일한지 확인했다. 각 가중치에서 고정 전진만 성공한 사례는 3건씩이었다. 출구 방향만 성공한 사례는 없었다. 출구 방향을 줬을 때 늘어난 실패는 시간 초과였다. 원래 전체 주행에서 실패한 자세 5건을 당시의 가중치와 지시로 재출발하면 2건은 완주하고 3건은 다시 실패했다. 재출발에서 속도·스캔 이력·센서 잡음 상태가 초기화되므로 이 차이를 자세 하나의 영향으로 해석할 수 없다.

정지 상태에서 시작하는 마지막 구간에는 고정 전진을 우선한다. 다음 실험은 출구까지 학습한 가중치를 고정한 채, 문을 지난 뒤 고정 전진으로 전환하여 처음부터 끝까지 연속 주행할 때도 개선되는지 확인한다. [전체 교차 비교와 같은 코스 대조](../experiments/post-door-policy-poses/summary.json)

### 추적 영상에서 방향 입력과 모터 출력 표시

Unity에서 `-teacherCaptureFollow -teacherCaptureSteering`을 함께 지정하면 시드 6400의 0번 코스처럼 방향 입력을 쓰는 정책의 추적 영상에 화살표 두 개를 그린다. 주황색 직선은 마지막 추론에 실제로 들어간 차량 기준 방향 벡터를 당시 차체 방향으로 월드 좌표에 옮긴 것이다. 청록색 곡선은 같은 추론의 좌·우 모터 명령으로 만든다. 평균 `(L+R)/2`는 전후진과 길이에, 반차 `(L−R)/2`는 굽는 방향과 크기에 대응한다. 곡선 크기는 영상에서 읽기 위한 시각화 스케일이다. 현재 정책의 출력은 매 스캔의 결정론적 모터 명령 한 쌍이다. 확률을 표시하려면 같은 관측에 분포를 출력하는 정책 또는 여러 설정에서 반복한 출력을 따로 평가해야 한다. 구현은 실험 브랜치 `efbb652`에 있다.

완주 648개 스캔과 충돌 536개 스캔에서 시각화를 켜기 전후의 시각, 위치·방향, 모터 명령, 충돌 횟수 및 지시 종류가 각 행에서 일치했다. ### LiDAR 노이즈에 따른 조향 분포

같은 평가를 `-teacherCaptureNoiseSamples 32`와 함께 실행했다. 실제 주행의 자세마다 노이즈 적용 전 Unity 레이캐스트를 한 번 얻고, 그 반환 거리에 기존 LiDAR 시뮬레이션의 거리 오차, 에피소드 고정 바이어스, 빔 드롭아웃을 독립 시드 32개로 다시 적용했다. 같은 시드의 스캔이 같은 모델 복제본으로 들어가므로 각 복제본의 스캔 이력에서도 노이즈가 이어진다. 복제본의 가중치, 주행 지시와 관측 자세는 모두 같다. 주행에는 기준 모델의 명령을 사용한다.

보라색 띠는 매 추론에서 좌·우 모터 명령의 반차 `(L−R)/2`를 폭 0.05의 구간으로 세어 나타낸다. 오른쪽 회전 명령이 양수이고, 진할수록 32개 중 해당 구간의 빈도가 높다. 띠의 각도는 차체 정면을 기준으로 명령을 100°/단위로 사상한 표시값이다. 이 분포는 정해진 주행과 모의 센서 노이즈에 조건부인 조향 민감도를 나타낸다. 시연과 같은 경로에서 센서 노이즈에 의한 출력 변화량을 분석하는 데 사용한다.

완주 643개, 충돌 536개 추론 시점의 조향 표본을 기록했다. 스캔마다 32개 표본의 90백분위수와 10백분위수 차이를 구했다. 전체 구간에서 이 폭의 중앙값은 완주 0.0083, 충돌 0.0090이었다. 두 번째 문 주변 33–39초의 중앙값은 각각 0.0096과 0.0096이었다. 기록 전체에서 최대 폭은 완주 49.3초에 0.0496, 충돌 50.8초에 0.0643이었다. 기준 주행 CSV는 완주 648행과 충돌 536행의 모든 열에서 기존 화살표 녹화와 일치했다. 구현은 실험 브랜치 `e542897`에 있다. ### 완주 영상 35초대의 방향 지시 확인

시드 6400의 0번 평가에서 주황색 화살표는 두 번째 문의 안쪽 목표점을 계속 가리켰다. 벽 후면은 약 8.836m이고 차체 중심이 그보다 0.28m 앞에 도달하면 전진 지시로 바뀐다. 35.5초 차량은 z=9.014m였고, 월드 방향은 (−0.935, +0.355), 실제 모델 입력인 차체 기준 (전진, 오른쪽)은 (−0.309, −0.951)이었다. 차량이 오른쪽으로 돌아 목표점이 차체 기준 왼쪽 뒤에 있었다. 고정 전진 지시로의 전환은 36.3초에 처음 관측됐다.

TorchScript로 완주 643개 추론을 재생해 명목 조향 `(L−R)/2`를 Unity 기록과 대조했다. 최대 절대 오차는 약 1.79e−7이었다. 35.5초에서 35.0초의 방향만 고정하면 조향이 +0.1312, LiDAR 이력만 35.0초의 것으로 바꾸면 +0.2068이었다. 실제 출력은 +0.1307이고, 월드 전진 지시를 일찍 주면 +0.1389였다. 이 자세에서 회전 출력의 변화는 방향 지시보다 LiDAR 이력 변화에 더 민감했다. 차량과 관측을 고정한 입력 개입 한 사례이므로 조기 전환의 폐루프 성능이나 과적합은 판정할 수 없다. ## LiDAR만으로 문 개구부와 통과를 추정하는 재생 실험

기존 6400–6403, 6500–6503의 문 코스 24회에서 기록한 360빔 스캔을 그대로 재생했다. 각 스캔을 차체 기준 평면 점으로 바꾸고, 직선 후보를 허프 누적과 직교 최소제곱으로 구했다. 같은 직선에 놓인 양쪽 지지점 사이에 1.40–3.60m의 간격이 있으면 개구부 후보로 본다. 이 범위는 시뮬레이션 문 폭에 맞춘 실험값이다. 연속 스캔 조건은 점-직선 정합으로 직전 스캔에 대한 이동과 회전만 추정해 후보를 이어 붙였다. 정합이 불량하면 추적을 초기화하고, 같은 개구부를 세 차례 이상 본 뒤에만 통과 상태를 계산했다. 마지막 관측 뒤에는 최대 2.5초만 추적을 유지했다. 검출과 정합에는 LiDAR 거리값만 사용했다. 창 구분과 정답 판정에는 기존 Unity 위치·방향과 문 치수를 사용했다.

- 다음 문 앞 0.30–4.50m의 11,084 스캔에서 가장 가까운 전방 후보가 맞았던 경우 4,363회, 틀렸던 경우 1,534회, 후보가 없었던 경우 5,187회였다. 추적을 사용한 선택에서는 4,300회가 맞고 2,737회가 틀렸다.
- 문 앞 0.30m부터 기존 전환선까지의 1,607 스캔에서 해당 문은 단일 스캔 후보에 422회(26.3%) 나타났다. 추적을 사용한 선택은 1,146회(71.3%)에서 해당 문을 유지했다.
- 정답 통과 40건 중 36건은 통과 뒤 1초 이내에 그 문과 일치하는 개구부 후보가 다시 관측됐다. 이 수는 정답을 이용해 사후 매칭한 관측 가능성이다. 실제 추적 통과 판정은 40건 중 25건을 정답 전후 1초 이내에 잡았고, 별도로 문과 일치하지 않는 이벤트를 3건 냈다. 6400/0은 첫 문을 0.3초 늦게 판정했고 두 번째 문은 놓쳤다.

추적은 문 근처에서 후보가 잠시 사라지는 문제를 줄였지만, 먼 쪽에서 잘못 고른 개구부도 유지했다. 차량 제어에는 연결하지 않았다. 개구부 양쪽의 벽이 얼마나 이어지는지 확인해 초기 후보를 선별하고, 실측 문 폭과 시야를 반영해 다시 비교한다. 이 기록의 스캔은 모두 기존 정책으로 주행한 궤적에서 얻었으므로 실제 검출기가 조향을 바꿨을 때의 완주율은 알 수 없다. 재생 도구는 실험 브랜치 `46baabe`에 있다. [전체·코스별 집계](../experiments/lidar-doorway-probe/summary.json)

## 같은 장면에서 좌·우 지시만 바꾼 폐루프 평가

영상 시드 6400/0의 한 자세에서는 조향이 방향 지시보다 LiDAR 이력에 더 민감했다. 실제로 선택 가능한 두 방향이 있을 때 현재 모델이 상위 지시를 따르는지 확인하기 위해 7200–7207 시드의 신규 Unity 코스에서 시험했다. 각 시드에 중앙 상자 우회와 진입 복도 뒤 좌우 갈림길을 하나씩 생성했다. 좌·우 한 쌍에서 지형, 시작 자세, LiDAR 노이즈 시드와 가중치가 같다. 지시 벡터는 장애물 왼쪽 또는 오른쪽의 통과 지점을 향하며, 차량 기준 단위 방향으로 변환한다. 중앙 구조물 뒤 0.30m부터는 두 조건 모두 맵의 전진 방향을 준다. 기존 문·출구 방향 CNN 체크포인트 한 개로 주행했다.

교사 대조가 실제로 양쪽을 통과하고 완주한 쌍만 점수를 낸다. 중앙 구조물 중간을 지나는 횡단선에서 차량 중심의 좌우 위치를 보간해 선택한 통로를 판정한다. 완주와 충돌은 별도로 센다. 첫 스캔에서의 모델 출력을 다음 스캔 행의 명령으로 읽어 `(L−R)/2`의 차이와 부호를 비교한다. 코스 및 집계 코드는 실험 브랜치 `a7f5874`에 있다.

교사가 16쌍 전부에서 좌우를 각 한 번씩 완주했다. 32건의 교사·모델 교차 대조에서 최초 위치, 방향, 지시 유형과 360개 LiDAR 빔이 모두 일치했다. 출발 시 월드 방향은 정면 기준 좌우 14.5–29.8°였다.

| 유형 | 좌우 지시를 모두 따른 쌍 | 두 지시에서 같은 쪽으로 간 쌍 | 모델 완주 |
| --- | ---: | ---: | ---: |
| 중앙 상자 | 2/8 | 6/8 | 16/16 |
| 좌우 갈림길 | 0/8 | 8/8 | 16/16 |
| 전체 | 2/16 | 14/16 | 32/32 |

32회 중 18회가 지시한 쪽을 통과했고 14회는 다른 쪽을 통과했다. 충돌은 없었다. 첫 명령은 16쌍 중 14쌍에서 오른쪽 지시의 조향 값이 왼쪽보다 컸으나, 차이의 중앙값은 0.0051이었다. 첫 명령이 두 지시에 각각 맞는 좌·우 부호를 낸 쌍은 1쌍이었다. 이 시험에서는 회피와 완주는 성공해도 지시가 분기 선택을 안정적으로 바꾸지 못했다. 기존 학습 코스와 같은 구성의 대조군이 없어 학습 맵 과적합과 조건 지시 학습 부족의 상대 기여는 판별할 수 없다. 이 16쌍은 평가용으로 두고, 다른 시드에서 같은 관측에 서로 다른 유효 경로를 짝지어 수집한다. ## 짝지은 좌·우 교사 자료를 추가한 하위 모델

시드 7300–7311에서 중앙 상자와 갈림길을 새로 샘플링하고, 각각 같은 출발 상태에서 좌·우 교사 경로를 수집했다. 양쪽 모두 지시한 통로로 완주했는지 궤적으로 판정하고, 두 주행의 첫 자세·LiDAR 360빔과 코스 로그가 일치하는지 대조한다. 7304·7309의 두 유형·좌우 8회는 검증용이며 나머지 40회를 학습에 추가한다. 기존 좌우 대조 시드 7200–7207은 폐루프 평가용으로 유지한다.

기존 출구 방향 모델의 학습 자료 구성에만 새 자료를 추가했다. 기존과 같은 4스캔 CNN, 초기 난수 시드 0, AdamW, 15에폭과 검증 MAE 기준으로 처음부터 학습한다. 검증 MAE는 기존 검증 세트에 새 좌우 검증 세트를 합쳐 계산한다. 최종 평가는 기존 16쌍의 통로 선택과 완주를 비교한다. 별도 평가에서 기존 6400–6403 문 코스도 다시 돌려 회귀가 있는지 확인한다.

수집한 24쌍의 48회가 모두 지시한 통로로 완주했고, 각 쌍이 같은 시뮬레이션 상태와 첫 스캔에서 출발함을 확인했다. 새 모델의 학습 자료는 197회·47,165개 창, 검증 자료는 35회·8,844개 창이다. 재현에 쓴 추가 자료 옵션은 `--direction-choice-recordings experiments/direction-choice-training/teacher/recordings`이며 구현은 실험 브랜치 `aa0f3e5`에 있다. 기존 검증 27회에서 모터 명령 MAE는 0.02182→0.02194, 새 좌우 검증 8회에서는 0.03928→0.01764였다.

## 좌우 짝 자료의 학습 비율 비교

기존 학습 창 38,761개를 그대로 사용하고, 새 좌우 자료 8,404개 중 각 에피소드에서 시간축에 고르게 배치된 25% 또는 50%의 창을 사용한다. 양쪽 진행과 두 코스 유형에 같은 비율을 적용한다. 선택된 각 창의 스캔 이력 4개는 원래 녹화에서 연속으로 읽는다. 창 수는 반올림해 각각 2,097개와 4,201개이고, 전체 학습 창은 40,858개와 42,962개다. 상자·갈림길 검증과 기존 검증 자료를 합친 8,844개 창을 두 모델에 동일하게 사용하고, 구조·초기 난수 시드·AdamW와 15에폭 설정을 고정한다. 에폭당 최적화 스텝 수는 창 수에 따라 달라진다.

같은 7200–7207 좌우 16쌍과 6400–6403의 교사 검증을 통과한 문 코스 10개에서 0%와 100%의 기존 결과에 대조한다. 여기서 25%·50%는 전체 훈련 자료의 비율이 아니라 새 좌우 자료를 얼마나 남겼는지다. 재사용하는 폐루프 코스는 비율을 비교하는 개발용 평가로 취급한다.

| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 0% | 2/16쌍 | 18/32회 | 32/32회 | 7/10회 | 3/10회 | 0/10회 | 8/10회 |
| 25% | 0/16쌍 | 16/32회 | 31/32회 | 4/10회 | 1/10회 | 5/10회 | 7/10회 |
| 50% | 4/16쌍 | 20/32회 | 31/32회 | 3/10회 | 4/10회 | 3/10회 | 4/10회 |

25%에서는 문 코스의 충돌이 줄면서 시간 초과가 늘었고, 좌우 지시를 주면 16쌍 모두 같은 쪽으로 갔다. 50%에서는 4쌍에서 지시가 통로를 바꿨으나 문 완주율은 100%와 같았다. 시험한 중간 비율에서는 기존 문 성능을 회복하면서 100% 조건의 지시 추종을 유지한 가중치가 없었다. 각 조건을 한 번씩 학습했으므로 비율 전반의 추세로 일반화하지 않는다. 후속 비교에서는 전체 주행을 균등하게 줄이는 대신 동일한 출발·접근 상황에서 지시만 바꾼 표본을 우선하고, 문을 지난 뒤 다시 진행 방향을 잡는 자료는 별도 그룹으로 통제한다. 구현은 실험 브랜치 `bff4e70`에 있다. ## 통로 선택 직전의 짝 자료 보강

7400–7411의 12개 신규 Unity 시드에서 중앙 상자와 진입 복도 뒤 갈림길을 생성했다. 중앙 구조물의 전면을 기준으로 0.67–0.99m 앞에서 시작하고, 그 구조물 중심에서 차체를 좌우 최대 0.16m 벗어나게 둔다. 초기 방향은 기존 전진축에서 ±15°를 샘플링한다. 같은 시드·유형의 좌우 주행에는 같은 위치, 각도 및 LiDAR 노이즈 시드를 준다. 교사만 선택된 통로로 가는 경로를 추종한다.

양쪽 경로가 실제로 지정된 측면을 지나 완주한 24쌍 모두에서 첫 자세와 360개 LiDAR 거리가 좌우 주행 간 일치했다. 분기하기 전의 학습 자료를 만들기 위해 각 원본 주행에서 차량 중심이 중앙 구조물 전면에 처음 닿는 행 직전까지 보관했다. 한 주행 안의 4스캔 이력은 연속으로 유지된다. 7404·7409의 8회는 검증에 넣었다. 학습용 40회에서 새로 얻은 창은 4,096개, 검증용 8회에서 얻은 창은 800개다. 기존 자료의 38,761개 창으로 돌아가 이 창만 추가하고, 이전과 같은 CNN에 15에폭을 사용했다. 50% 균등 추출 조건의 추가 창 4,201개와 규모는 유사하지만 출발 자세, 코스 및 검증 자료가 달라 시간 구간만 바꾼 통제 비교로 해석할 수 없다. 7200–7207 좌우 평가와 기존 6400–6403 문 평가는 같은 조건으로 재사용했다.
