# 실내 자율주행 연구 기록

맵·경로·센서 시뮬레이션과 CSV를 재현하는 방법은 [데이터 생성 방법](data-generation.md)에 정리한다.

## 2026-11-18 설계 결정

- 엔코더 없는 좌우 TT DC 구동과 앞 캐스터를 사용한다. 직진·회전은 기존 펌웨어로 확인했다는 사용자 설명을 기준으로 한다. 라즈베리파이 OS 손실 이후의 펌웨어 파일과 통신 규격은 확인 전이다.
- 1차 목표는 2D LiDAR로 복도 주행, 오른쪽 갈림길 진입, 목적지 정지를 수행하는 것이다. LiDAR 모델은 RPLIDAR A1 추정이며 실물 라벨로 확인한다.
- 전역 좌표와 누적 PWM 이동량 없이, 새 스캔으로 로컬 조향을 갱신한다. 상위 FSM은 복도 주행 → 갈림길 진입 → 새 복도 주행 → 도착 순으로 진행한다. 상태 전이는 입구, 새 복도의 벽 방향, 목적지 특징으로 판정한다. 입구가 여러 개면 코스의 관측 가능한 특징이나 경로 상태가 추가로 필요하다.
- 첫 단계 구현은 `lidar_control.py`의 양쪽 벽을 이용한 중앙 유지와 전방 정지다. 차체 전방이 x, 왼쪽이 y이며 LiDAR 설치 위치·각도를 반영한 점을 미터 단위로 받는다. 반환값은 목표 선속도와 각속도다.
- 첫 단계는 양쪽 벽과 전방 반사가 충분한 직선 복도를 전제로 한다. 반사가 부족하거나 스캔이 오래됐으면 정지한다. 속도와 시야 구간은 초기 가정이다. 정지 영역은 실제 차폭, 앞쪽 돌출부, 통신 지연 및 정지 거리를 반영해 설정한다. 갈림길 판정과 회전 상태는 실제 스캔을 확보한 뒤 검증한다.
- 스캔 수신, 명령 변환 및 전송은 실물 인터페이스 확인 후 연결한다. 연결 시 새 스캔이 끊겨도 주기적으로 정지 명령을 내리는지 먼저 확인한다. 비전과 화재 실험은 이번 단계에서 보류한다.

## 검증

- 합성 점으로 중앙 정렬, 좌우 편차별 조향 방향, 전방 장애물 정지, 오래된 스캔과 빈 스캔 정지를 포함한 6개 검증을 실행했고 모두 통과했다.
- 실차에서는 같은 코스에서 시작 위치와 각도를 바꾸어 반복한다. 시작 조건, 갈림길 진입 성공, 도달 여부, 접촉, 주행 시간을 기록한다. 장애물 실험은 LiDAR가 읽는 높이에서 진행한다.
- 이후 학습 정책을 실험할 경우 같은 코스, 상위 목표, 정지 조건을 유지하고 하위 조향만 바꿔 비교한다. Flow Matching의 출력 후보는 차체 기준의 짧은 경로로 둔다.

## 작업 기록 방식

설계나 코드가 바뀔 때마다 날짜별로 변경 이유, 검증에 사용한 입력과 결과, 실차에서 확인할 항목을 이 문서에 추가한다.

## 2026-11-18 초기 학습 범위와 평가 계획

- 연구 문제 1의 1차 검증은 소형 RC카급 플랫폼이 무적재 상태에서 출발해 지정된 실내 목적지까지 이동·정지하고, 경로상의 정적 장애물을 피할 수 있는지 확인하는 것이다. 물품 운반은 응용 배경으로 두며 적재 능력은 이번 검증 범위에서 제외한다. 정적 장애물이 통로를 완전히 막는 조건에서는 정지 여부를 별도로 기록한다. 비전 기반 SLAM, 보행자 회피, 화재 대응은 별도 검증이 필요하다.
- 시연 경로는 복도와 갈림길, 목적지의 관측 가능한 특징을 바탕으로 FSM에 지정한다. 1차 시연은 갈림길 하나와 목적지 하나를 사용한다. 학습 정책은 특정 맵의 좌표를 입력받지 않고, 최근 LiDAR 스캔과 로컬 목표(복도 따라가기, 오른쪽 통로 진입)를 받아 짧게 실행할 조향을 출력한다. 목표 변경과 도착 정지, 스캔 유실과 근접 장애물 정지는 외부 로직이 맡는다.
- 진행 순서는 규칙 기반 주행 → 합성 데이터 모방학습 → 기록한 실차 스캔에서 출력 확인 → 저속 실차 비교다. 2D 벽과 상자를 레이캐스팅해 가상 스캔을 만들고, 시뮬레이터의 정답 기하를 활용하는 교사로 목표별 저속 조향을 라벨링한다. 장애물 뒤로 지나갈 공간이 있는 상황에는 정지 외에 실제 우회 예시를 넣는다. 복도 폭, 갈림길 모양, 상자 위치, 시작 오프셋과 각도, 스캔 누락 및 좌우 구동 편차를 바꾼다. 모델은 작은 MLP부터 시작하고 전진 속도는 초기에 제한한다.
- 학습·검증은 스캔 프레임이 아니라 복도 배치 단위로 분리한다. 처음 보는 가상 배치에서 양쪽 정책을 폐루프로 비교한다. 실차에서는 소량의 스캔과 명령 로그를 우선 수집해 센서 범위와 조향 방향을 맞춘다. 같은 코스와 시작 오프셋, 동일한 정지 조건에서 목적지 도달률, 접촉률, 목표점 정지 오차, 주행 시간으로 비교한다. 실차가 한 장소뿐이면 다른 실제 환경으로의 일반화는 검증 범위 밖이다.
- 시간 부족 시 규칙 기반의 목적지 주행을 주 결과로 삼고, 모방학습은 완료된 검증 범위까지 비교 실험으로 기록한다. Flow Matching은 여러 우회 경로 후보를 생성할 필요가 생겼을 때 비교한다. 현재 단계에서는 설계를 기록했으며 학습 데이터 생성과 모델 학습은 시작 전이다.

## 2026-11-18 연구 초점 변경: 장애물 회피

- 연구 질문은 엔코더 없는 소형 RC카급 플랫폼이 2D LiDAR의 연속 관측만으로 실내 정적 장애물을 피하고 진행 방향으로 복귀할 수 있는가이다. 무적재 상태로 시험한다. 앞서 검토한 갈림길과 지정 목적지 주행은 후속 확장으로 둔다.
- 첫 코스는 직선 복도다. 상태는 복도 주행 → 장애물 접근 → 우회 → 복도 복귀로 구성한다. 통과할 공간이 부족하거나 관측이 끊기면 정지한다. 상자는 LiDAR 스캔 높이에서 관측할 수 있게 둔다.
- 장애물 없음, 좌우 한쪽만 통과 가능, 양쪽 통과 가능, 완전 차단을 따로 시험한다. 우회 성공은 접촉 없이 장애물을 지나 복도 주행으로 복귀한 경우로 정의한다. 우회 성공률, 접촉률, 완전 차단 시 정지 성공률을 각각 기록하고, 우회 시간은 보조 지표로 둔다.
- 모델의 목표는 현재 관측에서 통과 가능한 쪽으로 조향하고 복도 주행으로 복귀하는 것이다. 합성 LiDAR로 규칙 기반과 동일 조건에서 비교하고, 학습과 검증은 복도 배치 단위로 분리한다. 첫 구현은 규칙 기반 우회이며 현재 코드는 복도 중앙 유지와 전방 정지까지 구현되어 있다.

## 2026-11-18 첫 실험: 정지 상태에서 통과 공간 구분

- 목표는 모터 명령을 내리기 전에 상자와 벽 사이의 좌우 간격이 스캔으로 구분되는지 확인하는 것이다. 현재 코드는 합성 점 입력에서 빈 복도에서는 전진했고, 전방 정지 영역에 상자가 있는 입력에서는 좌측 통과 가능, 우측 통과 가능, 양측 통과 가능, 완전 차단 모두 정지했다. 이 검증은 기존 정지 동작의 기준이며 실측이나 우회 판단 검증은 아직 진행하지 않았다.
- 실차에서는 LiDAR 라벨과 스캔 수신을 확인하고, 차체를 복도 중앙에 고정한 채 빈 복도와 네 장애물 배치에서 스캔을 몇 초씩 기록한다. 각 배치에서 상자와 벽 사이 실제 좌우 간격도 잰다. 상자는 스캔 높이에 걸치도록 놓는다.
- 차체 전체 폭과 센서 장착 위치를 기록한다. 첫 통과 후보는 좌우 간격을 차폭과 양쪽 여유 폭의 합과 비교해 구분한다. 모서리와 회전 시 차체가 차지하는 공간은 저속 주행 전에 추가로 확인한다.
- 저장한 스캔에서 통과 후보가 실제 배치와 맞으면 규칙 기반 우회를 연결한다. 첫 실차 주행에 앞서 기존 펌웨어 전진·회전·정지 명령을 확인하고 저속 정지 거리를 측정한다.

## 2026-11-18 2D LiDAR 시뮬레이터 첫 구현

- `python3 lidar_sim.py`로 Tkinter 창을 연다. 차체는 고정하며 상자를 드래그할 때 복도 벽과 상자에 닿는 LiDAR 점과 전방 거리를 갱신한다. Reset으로 상자 위치를 초기화한다.
- `scan_ranges`는 화면 없이 호출할 수 있다. 기본 출력은 차체 전방부터 반시계 방향으로 1도씩 증가하는 360개 거리값(m)이다. 복도와 차체, 상자의 치수는 시뮬레이션 초기값이다. 센서 잡음, 차체 이동과 충돌, 교사 조향과 학습 데이터 내보내기는 이후 작업이다.
- 헤드리스 검증에서 360개 유효 거리값과 전후좌우 기준 거리를 확인했다. UI 콜백 검증에서 상자 이동 후 전방 거리가 약 1.83 m에서 4.90 m로 바뀌고 Reset으로 초기 위치가 복원됐다. 작업 환경의 X 디스플레이 연결과 가상 디스플레이 시작이 실패해 실제 창 표시는 검증하지 못했다.

- 시각화는 흰 배경에 벽·차체 윤곽, 회색 장애물, 검은 LiDAR 감지점과 진행 방향만 표시한다. 광선 장식과 색상 테마를 제거했다. 창 없이 렌더링 호출과 전방 거리 계산을 확인했다.

## 2026-11-18 스캔 플롯 정리

- Tkinter Canvas와 하단 패널을 Matplotlib 플롯으로 교체했다. 미터 축은 가로세로 배율을 같게 유지하고, 벽·장애물·차체는 윤곽선, LiDAR 반환점은 파란 점으로 표시한다.
- Matplotlib가 설치된 환경에서 `python3 lidar_sim.py`로 실행한다. 상자는 드래그하고 `r` 키로 초기화한다. `python3 lidar_sim.py --save scan.svg`는 초기 배치를 벡터 파일로 저장한다. PNG 출력도 가능하다.
- 화면 없이 SVG와 1600×760 PNG를 생성하고 PNG를 눈으로 확인했다. 드래그 시 전방 거리 갱신과 `r` 초기화 콜백을 확인했다. 데스크톱 창의 실제 DPI 표시는 이 환경에서 확인하지 못했다.

## 2026-11-18 Unity 수동 구동 단계

- 실차에서 확인한 구성은 엔코더 없는 노란색 TT DC 모터, 앞 캐스터, 상부 2D LiDAR다. 차체 치수, 뒷바퀴 중심 간격과 축 위치, 질량, LiDAR 장착 위치, 펌웨어 명령 형식 및 실제 속도·정지 반응은 미측정으로 둔다.
- Unity 6000.3.27f1용 프로젝트를 `unity_sim`에 추가했다. 에디터에서 폴더를 열고 **Research → Open Manual Drive Scene**을 실행하면 복도 장면을 만들거나 저장된 장면을 연다. Play의 Game 뷰에서 WASD 또는 방향키로 전후진·좌우 회전하고 키를 떼면 목표 속도가 0이 된다.
- 수동 입력은 좌우 정규화 명령 `[-1, 1]`로 변환한다. 각 뒷바퀴 위치에서 종방향 힘을 가하고 후륜 축의 횡방향 미끄러짐을 제한한다. 앞 캐스터는 별도의 접촉 모델 없이 수동 지지대로 가정하고, Rigidbody를 평면 운동으로 제한했다.
- 초기 가정은 차체 폭 0.30 m, 길이 0.40 m, 바퀴 중심 간격 0.24 m, 뒷축은 중심에서 0.12 m 뒤, 질량 0.80 kg이다. 최고 바퀴 속도 0.45 m/s와 응답 시정수 0.20 s도 가정값이다. 실차 데이터를 확보한 뒤 보정한다.
- 설치된 Unity 6.3 어셈블리로 C# 컴파일을 통과했다. 이 작업 환경에서는 라이선스와 Package Manager의 로컬 IPC 연결이 실패해 에디터 Play 검증이 막혔다. 첫 실행 검증은 동일한 양의 좌우 명령에서 직진, 반대 명령에서 회전, 명령 해제 시 정지, 상자 접촉 시 관통하지 않는지 확인하는 것이다. 이 단계 이후 차량에 수평 LiDAR를 연결한다.

- 이후 수동으로 생성했던 `unity_sim` 프로젝트를 삭제했다. 위 실행 경로는 이전 작업 기록이다. C# 파일 3개는 `/tmp/mini-lidar-unity-scripts.Fe6QRT`에 임시 백업했다.

- 같은 시드의 T자 좌·우 시험은 동일한 배치 및 시작 자세를 사용한다. CSV의 `-seedNNNNN`으로 재현한다. 학습은 기본 검증 유형에 더해 5개 중 1개 시드를 통째로 보류한다. 스캔 이력은 배치에 접근할 때 구성해 대량 수집 시 메모리를 절약한다.

[SLAMTEC A1M8 사양서](https://bucket.download.slamtec.com/7fe7e3656e811ab1a645753af40809f05fa7ddcd/LD108_SLAMTEC_rplidar_datasheet_A1M8_v2.4_en.pdf)
